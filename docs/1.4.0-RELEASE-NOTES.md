# Smart Citizen 1.4.0 — Tag Builder, Mining + Salvage Stats, Mission BP Polish

> ⚠️ **Heads-up if Windows blocks the installer:** Smart Citizen is not yet code-signed, and Windows 11's **Smart App Control** (SAC) blocks unsigned installers — Properties → Unblock does **not** help with SAC. To install:
>
> 1. Open **Settings → Privacy & security → Windows Security → App & browser control**.
> 2. Click **Smart App Control settings** and set it to **Off**.
> 3. Run `SmartCitizen-1.4.0-Setup.exe` and finish installation.
> 4. After install, you can return to the same screen and turn Smart App Control back on if you'd like.
>
> A code-signing certificate would remove this friction permanently. Smart Citizen is a free side project — signing will only happen if community donations cover the recurring cost.

## Headline

**Make the name tags yours.** Smart Citizen has been writing `[MIL-S2-A] FR-76` style tags onto component names for several releases — 1.4.0 ships a **Tag Builder** that lets you customise every part of that: element order, short/medium/long forms, separator, brackets, and whether the tag goes before or after the name. Missiles and ship weapons get the same treatment.

On top of that: brand-new **stat enhancements for ship-mounted mining lasers and handheld salvage tools**, a major polish pass on the mission rewards pipeline (multi-source blueprint pool merge, rank-tier sub-sections, component name annotations on every blueprint reward), an installer hardened against the unsigned-uninstaller class of regression, and a **Reset user.ini** Tools button for one-click stock restore.

## New features

### Tag Builder

A new section on the Enhancements tab lets you customise the bracketed annotations the generator writes onto component, missile, and ship-weapon names. Each category has its own tab with:

- **Element order**: drag the rows to reorder. Components default to `Class → Size → Grade`; missiles to `Ordinance → Size`; ship weapons to `Damage → Size`.
- **Per-element style dropdown**: Short / Medium / Long. The dropdown labels reflect the current short/medium/long mapping live — e.g. `Short (M)` for class, `Medium (MIL)`, `Long (Military)`.
- **Separator**: none, space, hyphen, underscore, period, slash.
- **Enclosing brackets**: none, square `[ ]`, round `( )`, curly `{ }`, angle `< >`.
- **Placement**: before the name (default) or after it.
- **Mapping editor**: change `Military → MIL → Military` to `Military → M → Mil` or any other short/medium/long triple you like. Per category.
- **Live preview row** updates as you change the config.

**Default-behaviour changes you'll notice on first re-extract** (all reversible via the UI):

- Guided missiles now include size by default: `[IR-S1] Marksman` instead of the old `[IR] Marksman`. Bombs are unchanged: `[S2]`.
- Ship weapons now receive a name tag by default: `[E-S2]` style (short damage letter + S-prefixed size). Previously they had none.
- Tag placement now defaults to **before the name** (`[MIL-S2-A] FR-76`). Pre-1.4.0 ship-component output appended the tag (`FR-76 [MIL-S2-A]`); the Tag Builder restores the prepend form most users expect. Switch back per-category via the Placement dropdown.

### Stat enhancements for mining lasers + handheld salvage tools

Two brand-new enhancement categories, alongside the existing component / weapon / ship / mission generators:

- **Ship-mounted mining heads** (Greycat Arbor, Lancet, Helix, Hofstede, Klein, Impact, Drak Golem, MPUV Arm) gain per-mode beam stats — Fracture / Extraction — plus the `SEntityComponentMiningLaserParams` modifier overlay.
- **Handheld salvage tools** (Greycat Renovar XTR, multitool salvage attachments) gain per-mode rate, efficiency, ramp, energy, heat, and wear values for Repair vs Salvage.

Both excluded by default from the pre-1.3.x output for scope reasons; toggle them on in the Enhancements tab.

### Reset user.ini (Config tab Tools)

A new **Tools → Reset user.ini** button on the Config tab wipes the active channel's `user.ini` in one click after explicit confirmation. The original file is renamed to `user.ini.bak-YYYYMMDD-HHMMSS` so the action is one-step undoable; a same-second double click can't clobber the prior backup. After reset, the table reloads against stock values without an interim close-time autosave overwriting your work.

## Mission rewards — major polish

### Multi-source blueprint pool merge

Pre-1.4.0, `scan_contract_generators` only kept the first `<BlueprintRewards>` per `(title, system)` pair. 4.8-era Adagio mining missions that award **both** FPS gear (one pool) **and** ship components (a second pool) from the same contract had half their reward list silently dropped. The fix merges every pool with order-preserving de-dup so all reward items surface under POTENTIAL BLUEPRINTS.

### Component name tags on every blueprint reward

Ship-component blueprints in the POTENTIAL BLUEPRINTS list now carry the same `[CLASS-Sx-grade]` annotation the components pipeline writes onto stock component titles. So a Covalex haul mission's reward list reads:

```
<EM3>POTENTIAL BLUEPRINTS</EM3>
- Balandin [MIL-S3-B]
- Palisade [IND-S1-A]
- Parapet [IND-S3-A]
- Rampart [IND-S2-A]
- Siren [MIL-S1-B]
...
```

Mining heads picked up the same treatment via an Item Type fallback: `[MIN-S0-B]` for Helix, `[MIN-S0]` for Arbor MHV (no Grade), etc. FPS gear and weapons stay un-annotated (no Size/Grade/Class header to derive from). The CIG-baked size prefix that some entity names carry (`S0 Helix`, `S00 Hofstede`) is stripped from the blueprint list so the tagged and bare names align visually.

### Rank-tier sub-section labels

Pools whose filename carries a Shubin/Headhunters-style rank token (`shubinrank0to1`, `shubinrank4`) now surface as a sub-section header inside POTENTIAL BLUEPRINTS:

```
<EM3>POTENTIAL BLUEPRINTS</EM3>
<EM4>[Stanton, Rank 0–1]</EM4>
- Surveyor-Go [IND-S0-C]
- Lawson Mining Laser
<EM4>[Stanton, Rank 4]</EM4>
- FullSpec [IND-S2-A]
- Arbor MH2 Mining Laser
```

Lets you tell at a glance which rewards a higher-rank tier of the mission unlocks. Pools with no rank token render as a single bare-system header as before.

### Regional sub-sections separated by a blank line

When a mission awards different pools in different systems / regions (Pyro RegionA vs Pyro RegionB), there's now a blank line between the bullet blocks so the eye can tell them apart instead of seeing one continuous wall.

## Critical fixes

### Mission descriptions ignored your Tag Builder config

The first cut of Tag Builder threaded the user's config through the component and ship-weapon name passes but missed the `entity_name_tags` lookup that feeds mission POTENTIAL BLUEPRINTS lists. Result: a user who set component class to `Long (Military)` would see ship component names use it, but a mission's blueprint reward list still showed the legacy `[MIL-S3-B]`. Fixed — the components TagConfig now flows into the scitem lookup, and a config change invalidates the cached pickle so the next extraction rebuilds with the new style.

### EMP devices and tractor beams sprouted a meaningless `[1]` tag

`item_NameMXOX_EMP_Device=[1] TroMag Burst Generator` and similar — the ship-weapon tagger was emitting a size-only tag for items in `ships/weapons/` that have no ammo damage breakdown (EMP devices, tractor / towing beams, mining lasers). The ship-weapon Tag Builder style is damage-keyed (`[E-S2]`); a `[size]`-only fallback was noise. Fixed: items without a resolvable damage type now get no ship-weapon tag.

### Covalex titles showed `[BP]` with no blueprint list in some bodies

Several Covalex titles — `Covalex_HaulCargo_AToB_title`, `Covalex_HaulCargo_SingleToMulti_title` — were tagged `[BP]` (correctly: every modern CareerContract variant of those titles awards blueprints) but several mission descriptions sharing the title had no POTENTIAL BLUEPRINTS section. Root cause: CIG also spawns those titles through older `ContractLegacy` wrappers that point at standalone pu_missions XMLs, and **none of the 419 ContractLegacy blocks in the dataset carry `BlueprintRewards`**. Those spawn paths award no BP, but their description text was being generated and emitted into the INI. Fixed: post-contractgen, orphan pu-only desc entries under a BP-tagged title are dropped from the INI so the title's `[BP]` claim only attaches to bodies that back it up.

### Installer crashed in ISCC + the upgrade-uninstaller race

- A Pascal block-comment in `installer.iss` contained `{app}` literally — Pascal block comments don't nest, so the `}` after `app` prematurely closed the comment and ISCC failed with `Identifier expected.` Fixed by switching the offending comment to Pascal's `(* ... *)` form.
- Tester reports of "unins000.exe was deleted" after running the installer pointed at the upgrade-uninstall race (and SAC / Defender quarantining the unsigned uninstaller). Installer now enables setup logging, hardens the per-install pre-checks, and adds a sanity ssPostInstall step.

## Improvements

### Installer Preview workflow

A new `.github/workflows/installer-preview.yml` builds a downloadable `SmartCitizen-{VERSION}-Setup.exe` artifact outside the standard release flow — two triggers: `workflow_dispatch` from the Actions tab against any branch, **or** adding the `build-installer` label to a PR (subsequent pushes to the labeled PR rebuild automatically). Artifacts retain for 30 days; a companion cleanup workflow deletes them on PR merge so Actions storage doesn't accumulate.

### Tooltips on widgets that were missing them

Several interactive widgets across the Config and Enhancements tabs had no hover text. Tooltips now cover the dropdowns, buttons, and toggles that lacked them. (Plus a small coach-mark widening pass so the in-app guided tour callouts don't truncate long labels.)

### HELP + tutorial sync

`HELP.md` and `assets/tutorial.json` (the coach-mark tour) updated to cover the Tag Builder, the new mining/salvage categories, and the Reset user.ini button.
