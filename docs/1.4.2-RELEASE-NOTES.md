# Smart Citizen 1.4.2 — Rep Tier Names, Discovered Items, Tag/Label Customization

> ⚠️ **Heads-up if Windows blocks the installer:** Smart Citizen is not yet code-signed, and Windows 11's **Smart App Control** (SAC) blocks unsigned installers — Properties → Unblock does **not** help with SAC. To install:
>
> 1. Open **Settings → Privacy & security → Windows Security → App & browser control**.
> 2. Click **Smart App Control settings** and set it to **Off**.
> 3. Run `SmartCitizen-1.4.2-Setup.exe` and finish installation.
> 4. After install, you can return to the same screen and turn Smart App Control back on if you'd like.
>
> A code-signing certificate would remove this friction permanently. Smart Citizen is a free side project — signing will only happen if community donations cover the recurring cost, **or** if Smart Citizen reaches enough adoption to qualify for a free certificate through the [SignPath Foundation](https://signpath.org/) open-source endorsement program. Until then: SAC-off install, SAC-on after.

## Headline

**Mission rewards now read like the game shows them.** Instead of generic `Tier 1 / Tier 2 / Tier 3`, multi-tier missions now display the actual reputation rank required for each tier — `Rookie`, `Jr. Contractor`, `Veteran Contractor`, etc. Pulled live from DataForge's standings data and the in-game loc keys, so the labels stay correct across game patches.

On top of that: a **discovered-items pipeline** that synthesizes enhancements for ships/components/missions whose loc keys are missing from `base.ini` (no more silently dropped entries), **commodities** join the Tag Builder as a fully configurable category, **components** get a new optional Type element (Shield, Cooler, etc.), and **Mission Labels** lets you rename every section header (MISSION DETAILS / POTENTIAL BLUEPRINTS / ITEM REWARDS / BLUEPRINT DATA), the XP label, and the emphasis tag used for headers.

## New features

### Reputation rank names on mission tiers (#95)

Multi-tier mission entries previously rendered as:

```
<EM4>Tier 1:</EM4> +25 XP
<EM4>Tier 2:</EM4> +100 XP
<EM4>Tier 3:</EM4> +200 XP
```

Now show the actual reputation rank the player needs for each tier:

```
<EM4>Jr. Contractor:</EM4> +25 XP
<EM4>Contractor:</EM4> +100 XP
<EM4>Sr. Contractor:</EM4> +200 XP
```

Names come from CIG's own `RepStanding_{Faction}_Rank{N}` loc keys, resolved via a new standings lookup that extracts `reputation/standings/` from DataForge. Falls back to `Tier N` for the ~37 contracts (mostly CleanAir bulk hauls) that use `ContractResult_ScenarioProgress` instead of a `minStanding` reference.

### Sub-contract missions are no longer dropped

CIG nests faction-specific mission variants (e.g. Shattered Blade Eckhart defend-ship missions) as `<SubContract>` elements inside parent contracts. Previously the scanner only read the parent's title/description, silently dropping **1,970 sub-contract variants across 64 contract files**. Now `scan_contract_generators` emits an additional variant per sub-contract, inheriting the parent's XP, blueprints, and difficulty. *"Stop Shattered Blade Attack"* and *"Request for Ship Support"* now appear with their `[BP]` tags and full Monde/R97 blueprint lists.

### Discover items from DataForge XML when base.ini doesn't list them

When the generator encounters a DataForge entity whose loc key isn't in `base.ini`, it now synthesizes a description from the XML (career/role/crew/length for ships, item type for components, tracking type for missiles, contract debug name for missions) and emits the entry as **status = New** (green). A new **Include discovered items** checkbox on the Config tab controls whether these flow into the applied `global.ini`. Covers ships, components, weapons, missiles, FPS weapons, and missions.

### Tag Builder: Commodities + Component Type

- **New Commodities category** alongside Components / Missiles / Ship Weapons. Default tag is `[CF]` on commodity names; fully configurable (text, brackets, placement) via the Tag Builder UI and a new mapping editor.
- **Optional Type element on Components** — disabled by default. Enable it to add Shield / Cooler / Power Plant / Quantum Drive / Radar to component tags (e.g. `[MIL-S2-A-SH]` for a military shield).
- **Per-kind Edit Mapping dialog** — clicking Edit Mapping on Class shows only Military/Civilian/etc.; clicking it on Type shows only Shield Generator/Cooler/etc. (instead of merging both into one confusing dialog).

### Mission Labels

A new section on the Enhancements tab makes every fixed string in the mission enhancement output configurable:

- **Section headers**: rename `MISSION DETAILS`, `POTENTIAL BLUEPRINTS`, `ITEM REWARDS`, `BLUEPRINT DATA` to whatever you want.
- **XP label**: the line shown on missions without a specific reputation rank now defaults to `Rep` (was `Reputation XP`); fully customizable.
- **Header emphasis tag**: pick `EM1` / `EM2` / `EM3` / `EM4` for section header styling — the four tags map to different sizes/colors in-game.

### Disable Tutorial setting

A **Disable Tutorial** checkbox on the Config tab's Appearance group stops the guided tour from auto-launching on new versions. Persists across reinstalls via the registry. The Tutorial button in the toolbar still works on demand.

## Critical fixes

### "Preliminary Bounty" no longer shows wrong blueprints (#47)

A dev-only contract (`notForRelease="1"`) shared the same description key as the released BHG FPS intro mission and had a blueprint pool attached. Result: Palatino/Moonfall items bleeding into "Preliminary Bounty" where they don't belong. Fixed: `scan_contract_generators` now skips handlers and contracts marked `notForRelease="1"`.

### Installer overwrote correct SC path with stale value (#94)

The pre-1.4.2 installer wrote `game_install_path` and `sc_directory` but never `sc_install_root`. On reinstall with a changed SC path, the stale `sc_install_root` from a prior migration survived and won over the freshly chosen directory. Surfaced for users with nested same-name directories (`HD4/STARCITIZEN/STARCITIZEN/LIVE`). Two-layer fix: the installer now writes `sc_install_root`, and `get_sc_install_root()` cross-checks against `game_install_path` to auto-correct stale values from older installers.

### First-run portable build no longer errors on missing SC path (#50)

Portable installs with non-standard SC paths failed after the welcome wizard with a hard error and a dialog whose Close button was greyed out. First-run now detects the missing path / missing `base.ini` combo and shows a friendly prompt directing users to the Config tab. DataForge extraction errors close the progress dialog before showing the error message, so the modal stack stays escapable.

## UI polish

- **Compact Enhancements tab layout** — Localization Enhancements grid is 3×2 instead of 2×3, Mission Labels uses a 3×2 grid, Favorites and Mission Labels share a horizontal row, Tag Builder description trimmed to one line, Tag Builder element rows sit side-by-side with the controls/preview column.
- **Tab layout pinned** — switching between tabs no longer shifts the toolbar/footer position. The `QTabWidget` now uses a stretch factor in the main layout so every tab gets the same vertical allocation.
- **Tutorial reordered + expanded** — 18 steps walking the workflow in actual data-flow order (Extract → Enhancements overview → 4 Enhancements section deep-dives → Edit/Filter/Editor/Preview → Apply → 5 Config section deep-dives → Help).
- **Tag Builder element-row widths equalized** so style dropdowns and labels align across rows.
- **DataForge extraction errors now close the progress dialog** before showing the error so it's actually dismissable.

## Other

- **odw-fast-unp4k binaries** updated (rebuilt on `.NET 8.0` single-file publish, ~64 MB vs ~70 MB).
- **Installer Preview workflow** now minimizes prior bot comments on PRs (via GitHub's `minimizeComment` GraphQL mutation) so a labeled PR with many pushes shows only the latest download link.
- **Configurable mission rendering threaded through the worker** end-to-end: `AppSettings` → `EnhancementsGeneratorWorker` → `generate_enhancements_ini.main()` → render paths. Settings are read on the main thread before the worker launches (matches the existing tag-config hand-off pattern).
- **New 4.8.0 SCMDB fixture** (`tests/fixtures/missions_4.8.0.csv`, 1,515 records) plus Kraken's `global.ini` and `contracts.ini` for cross-reference; new diagnostic scripts (`parse_scmdb_missions.py`, `diff_mission_fixtures.py`).
- **27 new unit tests** covering the backfill migration, install-root cross-check, `notForRelease` filter, and type/label tag rendering.
