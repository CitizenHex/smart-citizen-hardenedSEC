# Smart Citizen 2.2.1

> ⚠️ **Heads-up if Windows blocks the installer:** Smart Citizen is not yet code-signed, and Windows 11's **Smart App Control** (SAC) blocks unsigned installers, Properties → Unblock does **not** help with SAC. To install:
>
> 1. Open **Settings → Privacy & security → Windows Security → App & browser control**.
> 2. Click **Smart App Control settings** and set it to **Off**.
> 3. Run `SmartCitizen-2.2.1-Setup.exe` and finish installation.
> 4. After install, you can return to the same screen and turn Smart App Control back on if you'd like.
>
> A code-signing certificate would remove this friction permanently. Smart Citizen is a free side project, so signing will only happen if community donations cover the recurring cost, **or** if Smart Citizen reaches enough adoption to qualify for a free certificate through the [SignPath Foundation](https://signpath.org/) open-source endorsement program. Until then: SAC-off install, SAC-on after.

## Headline

Hey Smart Citizens! 2.2.1 is a bug-fix release, and two of those fixes are big ones: the starmap name corruption and the all-strings-broken `@KeyName` bug. If you hit either, this is your update.

## The two big fixes

### Crusader is Crusader again (#255, #257)

Some of you saw Crusader renamed to "Stanton (Star)" on the starmap, and other names quietly swapped around the verse. The cause was the feature that keeps related keys in sync (so editing a ship name updates all its variants): it was matching keys far too loosely and syncing strings that had nothing to do with each other. It now only touches item name and description keys, where it belongs. Your starmap is safe.

### No more @KeyName walls (#261)

After applying, some installs showed every string in the game as its raw key (`@vehicle_NameMISC_Prospector` instead of "Prospector"). The game wants the applied `global.ini` to start with a UTF-8 byte-order mark, and Smart Citizen wasn't writing one. It does now. While we were in there, every file-read path got hardened against corrupt or oddly-encoded files, so a bad byte in a cached file degrades gracefully instead of breaking the load.

## More fixes

- **Channel switching broke Generate Enhancements (#273).** Switching between LIVE, PTU, and HOTFIX left the app insisting DataForge wasn't extracted even when it was, and the button stayed stuck. Fixed, and the same refresh now covers Save Tag Changes and Apply Owned Tags too.
- **XenoThreat blueprints missing (#267).** Blueprints from XenoThreat missions never showed in the Blueprint Tracker. They do now.
- **Fuel nozzles and mining heads (#266, #281).** The Blueprint Tracker now recognizes the fuel nozzle and mining head families, including the ones whose in-game bullet names don't match their real item entries. Mission POTENTIAL BLUEPRINTS lists also stopped showing garbled fuel nozzle strings, and the parser understands "Multiple Blueprint Pools" headers and reputation-tier sub-headers.
- **Mission Titles checkboxes didn't save (#259).** Seven checkboxes on the Mission Titles page never armed the Save Tag Changes button, so toggling them alone couldn't be saved. All of them count now.
- **Install auto-detect across all drives (#269).** Smart Citizen now scans every local drive for your Star Citizen install instead of assuming the usual spot.
- **A crash in the translation helper.** A rare crash when a UI string's placeholder was named `key` is fixed.
